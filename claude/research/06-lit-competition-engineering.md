== RESEARCH SYNTHESIS: OGC 2026 ENGINEERING GUIDANCE ==

**A. PREVIOUS OGC EDITIONS (directly actionable intelligence)**
- OGC is in its 3rd year. OGC 2024 (1st edition): bundle-delivery dispatch (VRP-like, K orders, 3 rider types). Winner: SNU IE team "DMS". OGC 2025: RoRo car-carrier stowage (spatial packing + port LIFO precedence — structurally a cousin of the 2026 problem). Winner: SNU IE grad team "tryAgain", 343 teams/676 people. Finalist code + technical reports are made open source per rules.
- **The OGC 2024 WINNER'S FULL CODE IS PUBLIC and I cloned it to `/private/tmp/claude-501/-Users-vedantmoghe-Downloads-optichallenge/828d3afa-14fe-4679-bfb6-c94c0e22ac75/scratchpad/ogc2024-winner`** (github.com/syleeKR/Optimization-Grand-Challenge-2024). Study it — it is the revealed preference of the judges and the exact evaluation harness. Their architecture:
  - `myalgorithm.py` (thin Python entry) → **C++ ALNS engine via pybind11** (`src/c_backend/`, compiled by `build.sh`/`setup.py`) → **alternating with Gurobi set-partitioning** (`GurobiSP.py`) over the pool of bundles (columns) collected during ALNS. Loop: [ALNS burst → SP solve → warm-restart ALNS from SP solution] several rounds, sized by a per-instance time schedule.
  - Classic Ropke–Pisinger ALNS: destroy ops = Shaw/worst/semi-worst/route removal (5–15% of solution destroyed, `min_prob=0.05,max_prob=0.15`), repair ops = regret + randomized greedy insertion; adaptive operator weights (scores 20/10/2, rho=0.5, update every 100 iters); simulated-annealing acceptance with tuned modify-ratio.
  - **Per-instance parameter tables keyed by an instance fingerprint** (`get_prob_num(K, timelimit)` matches hidden-instance sizes; falls back to `get_general_timelist_and_anneal` for unseen sizes) — i.e., they hard-tuned time splits/annealing per instance class and kept a robust general fallback.
  - Explicit time-budget ledger: `SPARE_TIME` safety margin (0–3.5 s), last round sized as `timelimit - elapsed - SP_TIME - SPARE`, and `timelimit -= 10` for the largest instances because the server clock bit them. Copy this paranoia.
- Implication for 2026: the committee rewarded ALNS+column-generation-style matheuristic with C++ core last time; "novel ideas valued" means you should keep that skeleton but the novelty budget should go into the problem structure (crane j>=k precedence digraph, assignment/bay decomposition, same-day exit-before-entry space reuse).

**B. WHAT SEPARATES TOP-3 FROM MID-PACK (ROADEF/EURO evidence)**
- ROADEF 2018 (glass cutting) winner Libralesso & Fontan: **anytime tree search (Memory-Bounded A* with guide functions, symmetry breaking, pseudo-dominance)** beat all metaheuristics among 64 teams; the same pair won 2022 (truck loading) with tree-search-based PackingSolver. Lesson: for packing-flavored problems, a well-guided constructive tree search with restarts is a legitimate winner-class alternative/complement to LNS — and it is inherently anytime and never-infeasible.
- ROADEF 2020 (RTE maintenance) winner Buljubasic & Vasquez: **scenario-penalization matheuristic** — progressively reparameterized objective + shift/swap local search; runner-up class used ILS with self-adaptive perturbation; published ALNS entries reached top-5. Lesson: winners exploit one structural insight deeply rather than stacking generic operators.
- ROADEF 2012 (Google machine reassignment): top entries were MIP/CP-based LNS hybrids.
- Cross-cutting separators: (1) solution representation that makes moves O(1)-evaluable (incremental delta evaluation, event calendars, interval trees) — mid-pack re-evaluates from scratch; (2) anytime + checkpointing — always hold a feasible incumbent; (3) per-instance adaptation (detect size/slack/bay-count and switch config); (4) C++/compiled hot loop, Python only as shell; (5) ruthless time-budget management with margins; (6) portfolio/restart: run 2–4 differently-seeded/parameterized searches on your 4 cores and take the best, rather than one parallel search.

**C. MATHEURISTICS — WHEN GUROBI PAYS OFF UNDER 4 CORES / ≤30 MIN**
- Best ROI here (mirrors the OGC 2024 winner's SP pattern): **assignment master problem**. Z2 (workload balance) + Z3 (preference regret) depend only on bay(i). Solve a small MIP/ILP: binary x_ij, linearized max-pairwise-imbalance, plus a learned/estimated per-bay "congestion→tardiness" penalty from slave feedback; re-solve every macro-iteration. n·m ≤ 1500 binaries — Gurobi solves this in milliseconds-to-seconds. This is your two-level decomposition master.
- Second ROI: **single-bay resequencing**: given a fixed set of blocks in a bay and fixed geometry "capacity profile", weighted-tardiness sequencing (1|r_j|ΣwT_j-like) over ≤80 blocks via Gurobi time-indexed or disjunctive model with tight time limit (2–10 s), or via exact DP on small clusters. Use it as a *repair/polish* operator inside LNS, not as the main engine.
- Set-partitioning over packing columns (placement patterns per bay-time-window) is the most "novel-report-friendly" option but risky: column feasibility checking is the expensive part. Only viable if your fast geometry kernel (below) makes pattern generation cheap.
- Rules of thumb: MIP wins when the subproblem is (a) small (≤ few thousand binaries), (b) called with warm starts, (c) evaluated exactly by the same cost the checker uses. Never let Gurobi own the wall clock — cap every solve (`TimeLimit`, `MIPFocus=1`, `Threads=1` per solve so 4 solves run in parallel across bays).

**D. PYTHON PERFORMANCE UNDER THE SANDBOX**
- **Never call shapely in the inner loop.** Precompute geometry once per (block, orientation, layer): integer-grid rasterization of each layer polygon (bitmap/occupancy grid per bay at 1-unit resolution — positions are integers!) or no-fit-polygon precomputation per pair. Given integer placements and bay sizes ≤180×29 (~5220 cells), **bitmaps + numpy/numba bitwise AND are the dominant approach**: overlap test = O(words); candidate positions via 2D convolution/FFT or sliding-window feasibility masks. State-of-the-art nesting uses exactly NFP-or-raster (see CDE/sparrow papers, arXiv 2508.08341, 2509.13329). Careful: checker counts overlap only if area>0 and rounds x,y to int — rasterize conservatively so that your notion of "free" is a subset of shapely's (validate raster vs shapely on training; keep a shapely final verification pass before output).
- numba 0.61: use `@njit(cache=True)` and set `NUMBA_CACHE_DIR` to a writable dir (sandbox home may be read-only; firejail-style sandboxes often break the default `__pycache__` location — set env var in `myalgorithm.py` before importing your kernels). Budget ~5–20 s cold JIT on first call; warm the kernels on a tiny dummy instance at import time so JIT cost is paid predictably inside the limit. `numba.pycc` AOT is deprecated — don't rely on it. Cache invalidation does NOT track cross-module edits — bump a dummy constant or clear cache when editing helper modules.
- Better: the rules allow **C/C++ .so compiled for Ubuntu 24.04** — the OGC 2024 winner shipped pybind11 C++; that removes JIT risk entirely. Ship prebuilt .so + a build-at-first-run fallback + a pure-numba fallback (triple redundancy).
- Multiprocessing on 4 cores: per-bay slaves are embarrassingly parallel post-assignment. Use `multiprocessing.get_context("fork")` (Linux eval box) with preloaded read-only globals to avoid pickling geometry; or simpler: 4 worker processes each running an independent full-portfolio seed, master keeps best-of. Beware: ortools/gurobi may spawn threads — pin `Threads=1`; oversubscription on 4 cores destroys throughput. Set `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`.
- Profile with the checker's own stage-5 replay to make your internal evaluator bit-identical to `utils.py` — mid-pack teams lose to silent evaluator mismatches.

**E. ROBUSTNESS — NEVER SCORE -1**
- Wrap `algorithm()` in try/except + `signal`/deadline watchdog: compute hard deadline = start + timelimit − margin (use ≥3–5% or 5–15 s; winner used explicit SPARE_TIME and even shaved 10 s on big instances because the server clock differed). On expiry or exception, emit the best checkpointed feasible solution.
- Maintain an **always-feasible incumbent from second ~1**: build the trivial serialized fallback (each block alone in an empty-bay time window far in the future) immediately, then greedy baseline, then improve. Every improvement is validated (with your fast checker, spot-audited with shapely) before replacing the incumbent. Serialize incumbent to the output dict format continuously, not at the end.
- Defensive per-instance triage at t=0: n, m, total area pressure Σ(area·P)/(Σbay_area·horizon), slack distribution (D−R−P), single-bay case (Z2 undefined/zero? verify checker), zero-slack blocks, blocks that fit only one bay/orientation, degenerate polygons. Branch to configs: "loose" (pure due-date insertion suffices), "tight" (full LNS), "huge-n" (coarser candidate sets, cheaper operators).
- Determinism: fixed seeds per (instance-fingerprint, worker); no wall-clock-dependent branching in solution content, only in stopping.
- Memory: 16 GB / 4 workers — cap NFP/bitmap caches; prefer per-bay bitmaps over global pairwise NFP tables when O_i·K_i·n pairs explode.

**== 5 HIGHEST-LEVERAGE PRACTICES ==**
1. **Mine the OGC 2024 winner repo (already at scratchpad/ogc2024-winner) and clone its macro-architecture**: thin Python entry → compiled C++ core → ALNS (adaptive destroy 5–15%, regret repair, SA acceptance) alternating with a small Gurobi master — here the master = bay-assignment MIP over Z2+Z3+congestion feedback, slaves = per-bay tardiness packing, parallel over 4 cores.
2. **Bitmap geometry kernel** exploiting integer coordinates and tiny bays (≤180×29): per-layer occupancy grids, numba/C bitwise overlap and candidate-position masks; shapely only for one final validation pass identical to the official checker. This is a 100–1000× speedup over the baseline's shapely loop and multiplies every other idea.
3. **Exploit the crane j≥k structure as a precedence digraph** (overhang ⇒ induced LIFO exit order) plus same-day EXIT-before-ENTRY reuse: encode schedules as sequences + this digraph so moves are checked/evaluated incrementally — a representation-level insight, worth more than any operator tuning, and the "novel idea" for the technical report (tie it to spatial-scheduling literature: two-stage priority-rule + bottom-left-fill variants, SLACK rules minimizing tardiness).
4. **Anytime, never-infeasible design**: trivially-feasible solution at t≈0, continuously checkpointed incumbent in output format, hard deadline with 5–15 s margin, try/except everything, per-instance config triage with a robust general fallback (exactly the winner's `get_general_timelist_and_anneal` pattern).
5. **Portfolio + per-instance adaptation over 4 cores**: 4 processes (distinct seeds/operator mixes or per-bay decomposition), best-of-pool merging; instance-fingerprint-keyed parameter tables tuned offline on train sets 1/2, with all solver/BLAS threads pinned to 1 and numba caches pre-warmed (NUMBA_CACHE_DIR set) or a prebuilt Ubuntu .so to eliminate cold-start.
